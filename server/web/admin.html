A group is a filter on the map (e.g. Cubes, Gathering, Chests) and gives its kinds their color.

Kinds - what clients report

TypeTemplate IDNameGroupRespawn (min)ReportSpots

A kind is one template id (the "ID" column of the Objects tab in Cube Watch). Connected clients are told at once which kinds to report and what they are called. Leave "Respawn" empty to let the backend estimate it from the takes and spawns it sees. Deleting a kind deletes its spots and their history.

Spots

#KindMapXYZNowLast takenDetectedTakenAvg. pickupRespawnLabelHidden

A spot is a place where a kind was seen (positions within a metre are the same spot). A label shows on the map instead of the kind's name; a hidden spot stays in the database but is not drawn. Deleting a spot deletes its history - it comes back when a client sees something there again.

Maps

MapMap idsDrawn onSpotsPlayers now

"Asmodian lands" is built in (it has an image) and always there. Every other map is yours: a name and the map ids that belong to it, drawn on a grid - nothing from it is ever put on another map's image. A map id something was reported from and that has no name yet is listed as "not named" - type a name and press Enter. The quickest way is in "Clients" below: type the map's name next to a character that is there.

Calibration of the built-in map
MapImageScale X (px / unit)Scale YOffset X (px)Offset Y

Map images are compiled into the server (server/assets, see maps.json there). A pixel is offset + scale × world coordinate. To calibrate: note your X / Y in Cube Watch at two places far apart, find the same two places on the image (pixel position, e.g. in an image editor), enter both pairs above and press "Compute", then Save. Reports from any of the map ids are shown on this image.

Game servers

IdNameFromPlayers nowSpots with a state

The game servers something was reported from. Names come from the official list (compiled in, refreshed from the official site once a day). An id without a name there - the game uses ids of its own for shared zones like the Abyss - can be named here; an empty name takes your name away again. "Not known yet" is not an id: it is a client that has not learned its game server.

Online now

CharacterIs on mapPlayerGame serverClassXYConnectedLast message

"Is on map": the game only gives a map a number. When you know where a character is, type the map's name next to it (the known ones are suggested) and press Enter - the map id that client reports gets the name. A name that exists adds the id to that map (several ids can share a map); a new name makes a new map. A client that was started in the middle of a session learns its map id when the character changes zone.

What is around

DistanceTypeTemplate IDXYZNameGroup

"What is around" asks that client for everything it sees, nearest first - also things that are not tracked yet. Stand next to the thing in the game, press the button, type a name in the first row and "Track": it becomes a kind and all clients start reporting it.

All characters

PlayerCharacterGame serverClassLast seen

Every character a Cube Watch ever reported with, online or not, grouped by installation (the random id each Cube Watch makes on its first run - only its first characters are shown). The player seen most recently is on top.

Database - export / import

↓ Export database (.db)

Import merges another backend database into this one: groups are matched by name, kinds by (type, template id), spots by position (the same metre of the same map), history by (game server, spot, time, event) - the history of both databases interleaves chronologically and duplicates are skipped. Importing the same file twice changes nothing. Use export to move data (a consistent copy even while running).
"Import Cube Watch history" takes the data\cubes_*.csv files Cube Watch wrote before there was a backend (select several at once): every cube in them becomes a sighting at its place, so all places known so far are on the map with how often a cube was detected there. Importing a file twice adds nothing.
